**Create skills/weekly-review/SKILL.md:**

**Frontmatter:**
```yaml
- - -
name: weekly-review
description: Use when doing the weekly review, GTD review, or weekly planning session. Use when user says "weekly review", "revision semanal", "review", "revisemos la semana", "GTD review".
- - -
```

**Step 0 -- Load configuration:** Standard pattern. Set VAULT.

**Overview:** Interactive GTD weekly review facilitator. Walks through each review step, presenting data and waiting for user input at each stage. This is a conversation, not a report.

**Process:**

### 1. Start review
```
Iniciamos la revision semanal. Voy a guiarte paso a paso.
Puedes escribir "saltar" en cualquier paso para ir al siguiente.
```

### 2. Retrospective
Read previous week's daily notes from `VAULT/{config.structure.daily_notes}/`.
Present:
```
## Paso 1: Retrospectiva

Completadas esta semana: X tareas (Y trabajo, Z personal)
Energia media: [emoji trend from Cierre sections]

Dias con energia alta: X
Dias con energia baja: Y

Logros destacados:
- [extracted from daily note logs and completions]
```
Ask: "Como fue la semana? Algo que agregar a la retrospectiva?"
Wait for user response. Capture.

### 3. Inbox zero check
Read `VAULT/{config.structure.inbox}`.
```
## Paso 2: Inbox Zero

Items en el inbox: X
```
If inbox has items: "Hay X items sin procesar. Procesamos ahora? (s/n)"
- If yes: run process-inbox logic inline (classify, suggest, confirm, apply)
- If no: "OK, queda pendiente. Recuerda procesar antes de empezar la proxima semana."

If inbox empty: "Inbox limpio! Bien hecho."

### 4. Backlog health
Read `VAULT/{config.structure.backlog}`.
```
## Paso 3: Salud del Backlog

Total tareas pendientes: X
- #next: Y
- #esperando: Z
- Sin tag de accion: W

Arrastradas >2 semanas: A tareas
[list dragged tasks]
```
If dragged tasks exist: "Estas tareas llevan mas de {config.weekly.dragged_task_alert} dias. Para cada una: mantener / reprogramar / archivar / someday?"
Present each dragged task for decision. Apply changes after batch confirmation.

### 5. Stalled projects
Read `VAULT/{config.structure.projects}/` and cross-reference with Backlog (same logic as /projects skill).
```
## Paso 4: Proyectos Parados

Proyectos activos: X
Parados: Y
[table of stalled projects with reason]
```
For each stalled project: "Proyecto [[Name]] esta parado: [reason]. Quieres agregar un next action? (escribelo o 'saltar')"
If user provides a next action, add it to Backlog with project tag + #next.

### 6. Someday/maybe review
Read someday items from Backlog (same logic as /someday skill).
```
## Paso 5: Algun Dia / Someday

Items en someday: X
[list items]
```
Ask: "Hay algo que quieras promover a activo esta semana? (numeros separados por coma, o 'ninguno')"
If user selects items: ask for context tag and week tag, move to active section in Backlog.

### 7. Goal progress snapshot (GOAL-05)
Read `VAULT/{config.structure.goals}`.
```
## Paso 6: Progreso de Objetivos

| Objetivo | Progreso | Cambio semanal | Deadline |
|----------|----------|----------------|----------|
| [goal] | X/Y (Z%) | [delta from last history entry] | DD MMM |
```
For each in_progress goal: "Progreso actual de '[name]': {current}. Actualizar? (nuevo valor o Enter para mantener)"
If user updates: set `current` to new value. After all goals reviewed, append a history[] entry for each goal:
```yaml
- date: YYYY-MM-DD  # today
  value: {current value}
  note: "Weekly review snapshot"
```
This is the automatic weekly snapshot that fulfills GOAL-05.

### 8. Plan next week
Read calendar for next week. Read goals.
```
## Paso 7: Plan de la Proxima Semana

Reuniones proxima semana: X (Yh)
Foco disponible: ~Zh

Prioridades sugeridas basadas en objetivos:
1. [highest weight goal with most gap]
2. [next]
3. [next]
```
Ask: "Estas de acuerdo con las prioridades? Ajusta o confirma."
Wait for user input.

### 9. Generate weekly note
Run /week generation logic to create/update the weekly note with all data collected during the review.

### 10. Git safety and commit
Before any writes during the review:
- `git -C VAULT add -A`
- `git -C VAULT commit -m "backup: before weekly review"`

After all changes:
- `git -C VAULT add -A`
- `git -C VAULT commit -m "ritual(weekly-review): week YYYY-W##"`

### 11. Summary
```
Revision semanal completada:
- Retrospectiva: capturada
- Inbox: [limpio / X items procesados]
- Backlog: X tareas revisadas, Y reprogramadas
- Proyectos: Z parados atendidos
- Someday: W items promovidos
- Objetivos: progreso actualizado, snapshots guardados
- Plan proxima semana: prioridades confirmadas

Weekly note: {path}
```

**Graceful Degradation:**
| Missing | Behavior |
|---------|----------|
| No daily notes for previous week | Skip retrospective, note "Sin dailies de la semana anterior" |
| Empty inbox | Skip inbox step, note "Inbox limpio" |
| No projects folder | Skip stalled projects step |
| No goals.yaml | Skip goal progress step |
| User says "saltar" at any step | Move to next step |

**Important Rules:**
- This is INTERACTIVE -- wait for user input at EVERY step
- NEVER auto-apply changes -- always confirm (per D-15)
- Git safety before any writes (per D-14)
- Each step reads FRESH data (not cached from start)
- User can skip any step by typing "saltar"
- Spanish language for all output
- Goal history snapshots are append-only -- never modify past entries

**Frontmatter:**
```yaml
- - -
name: quarterly
description: Use when doing quarterly reflection, goal review, or planning the next quarter. Use when user says "quarterly", "trimestral", "quarterly review", "revision trimestral", "goal review", "revision de objetivos".
- - -
```

**Step 0 -- Load configuration:** Standard pattern. Set VAULT.

**Overview:** Interactive quarterly reflection workflow. Reviews each goal's progress over the quarter, facilitates start/stop/continue analysis, and helps set next quarter goals. Generates a quarterly reflection note.

**Process:**

### 1. Determine quarter
Calculate current quarter (Q1=Jan-Mar, Q2=Apr-Jun, Q3=Jul-Sep, Q4=Oct-Dec) and year. If user specifies a quarter, use that instead.

### 2. Read goal data
Read `VAULT/{config.structure.goals}`. Filter goals by horizon = "quarterly" (or goals whose deadline falls within this quarter).

### 3. Goal-by-goal review
For each goal, present:
```
## Objetivo: [name]
Dimension: [dimension]
Metrica: [metric]
Progreso: [current]/[target] [unit] ([%])
Deadline: [deadline]

Historial:
| Fecha | Valor | Nota |
|-------|-------|------|
[history entries for this quarter]

Tendencia: [improving/declining/flat based on history]
```
Ask: "Como evaluas este objetivo? (1-5) y comentario"
Wait for user response. Capture rating and comment.

### 4. Start/Stop/Continue analysis
After reviewing all goals:
```
## Start / Stop / Continue

Basado en la revision:

**Continue (objetivos que van bien):**
- [goals with good progress and positive rating]

**Stop (objetivos que abandonar o pausar):**
- [goals with poor progress or low rating]

**Start (nuevas ideas para el proximo trimestre):**
- [ask user]
```

Ask: "Que quieres EMPEZAR el proximo trimestre?"
Wait for response.

Ask: "Algun objetivo actual que quieras PARAR o pausar?"
Wait for response. If user wants to stop a goal, set its status to "abandoned" in goals.yaml.

Ask: "Algo mas que quieras CONTINUAR con ajustes?"
Wait for response. If user wants to adjust, update target/deadline/weight in goals.yaml.

### 5. Set next quarter goals
Ask: "Quieres definir nuevos objetivos para Q[next]? (s/n)"
If yes, for each new goal, walk through the /goal add flow:
- name, dimension, horizon, metric, target, weight, deadline
- Add to goals.yaml

Remind about weight validation: "Los pesos de objetivos quarterly suman X. Deben sumar 1.0."

### 6. Generate quarterly note
Create `VAULT/{config.structure.weekly_notes}/YYYY-Q#-reflection.md`:
```markdown
- - -
tags: quarterly
quarter: YYYY-Q#
date: YYYY-MM-DD
- - -

# Reflexion Trimestral Q# YYYY

## Resumen de Objetivos

| Objetivo | Resultado | Rating | Comentario |
|----------|-----------|--------|------------|
| [goal] | X/Y (Z%) | [1-5] | [user comment] |

## Progreso Global Ponderado: X%

## Start / Stop / Continue

### Empezar
- [user inputs]

### Parar
- [user inputs]

### Continuar
- [user inputs]

## Objetivos Q[next]

| Objetivo | Dimension | Metrica | Target | Peso | Deadline |
|----------|-----------|---------|--------|------|----------|
| [new goals] | ... | ... | ... | ... | ... |

## Reflexion Personal

[user's free-form reflection if provided]
```

After all changes:
