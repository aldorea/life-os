**Step 0 -- Load configuration:** Standard config.yaml loading. Set VAULT.

**Overview:** CRUD skill for goals stored in `VAULT/{config.structure.goals}` (goals.yaml). Supports add, update, list, progress, and remove operations.

**Process:**

### 1. Determine operation
Parse user input to identify the operation:
- `/goal` or `/goal list` -- list all goals grouped by dimension
- `/goal add` -- add a new goal
- `/goal update <id>` -- update a goal's fields
- `/goal progress <id> <value> [note]` -- record progress (append to history[])
- `/goal remove <id>` -- mark goal as abandoned (never delete)

### 2. Read goals.yaml
Read `VAULT/{config.structure.goals}`. If file doesn't exist, create it with empty `goals: []` array and continue.

### 3. Execute operation

**For `list`:**
Group goals by dimension (professional, personal, health). For each goal show:
```
## Objetivos

### Profesional
| ID | Objetivo | Métrica | Progreso | Peso | Deadline | Estado |
|----|----------|---------|----------|------|----------|--------|
| revenue-q2 | Aumentar revenue... | Revenue mensual | 9500/12000 EUR (79%) | 35% | 2026-06-30 | in_progress |

### Personal
...

### Salud
...

Peso total por horizonte:
- Quarterly: X (debe ser 1.0)
- Annual: Y (debe ser 1.0)
```

**For `add`:**
Ask user for each required field:
1. id (suggest slug from name)
2. name (in Spanish)
3. dimension: professional | personal | health
4. horizon: quarterly | annual
5. metric (what is measured)
6. target (numeric)
7. current (numeric, default 0)
8. unit (optional, e.g., EUR, %, semanas)
9. weight (0.0-1.0)
10. deadline (YYYY-MM-DD)
11. status (default: not_started)

Present the complete goal object for confirmation before writing.

**For `update <id>`:**
Find goal by id. Show current values. Ask which fields to change. Present updated goal for confirmation before writing.

**For `progress <id> <value> [note]`:**
Find goal by id. Update `current` to new value. Append to `history[]`:
```yaml
- date: YYYY-MM-DD  # today
  value: <value>
  note: "<note or empty string>"
```
Show progress change: "revenue-q2: 9500 -> 10200 EUR (85% del target)". Confirm before writing.

**For `remove <id>`:**
Find goal by id. Set status to `abandoned`. Do NOT delete from file. Confirm before writing.

### 4. Weight validation (per Pitfall 8)
After any add/update/remove operation, check if weights within the same horizon sum to 1.0:
- Sum weights of all non-abandoned goals with horizon=quarterly
- Sum weights of all non-abandoned goals with horizon=annual
- If either sum != 1.0, warn: "Los pesos de objetivos [horizon] suman X, deberían sumar 1.0. Ajustar? (s/n)"

### 5. Git safety (per D-14)
Before writing goals.yaml:
1. `git -C VAULT add {config.structure.goals}`
2. `git -C VAULT commit -m "backup: before goal mutation"`
3. Write changes
4. `git -C VAULT add {config.structure.goals}`
5. `git -C VAULT commit -m "goal([operation]): [description]"`

**Graceful Degradation:**
| Missing | Behavior |
|---------|----------|
| goals.yaml doesn't exist | Create with empty goals array |
| Goal id not found | Show error, list available ids |
| git not available | Skip git steps, warn user |

**Important Rules:**
- NEVER delete goals -- only mark as abandoned
- ALWAYS validate weights after mutations
- ALWAYS present changes for confirmation before writing (per D-15)
- Spanish language for all user-facing text
- history[] entries are append-only -- never modify past entries
