name: sync-jira
description: Syncs Jira tickets from configured projects to the vault as individual markdown notes. Creates inbox items for new assignments and action-requiring status changes. Use when user says "sync jira", "sincroniza jira", "revisa jira", "tickets".

**Step 0 -- Load configuration:** Same pattern as sync-slack. Read `${CLAUDE_PLUGIN_ROOT}/config.yaml`, set VAULT, check for config existence.

**Overview:** Connector that syncs Jira tickets from multiple configured projects via MCP servers into individual vault notes. Creates inbox items only for new assignments or action-requiring status changes (per D-05). Each Jira project maps to a configured MCP server (per D-01).

**Prerequisites:**
- At least one Jira MCP server must be available (mcp__{server_name}__jira_search)
- If no MCP server responds, warn and skip gracefully

**Process sections:**

### 1. Read Jira project config
Read `VAULT/{config.structure.connectors_config}` and parse the `jira.projects` array. If no jira section exists, warn user to configure connectors.yaml and stop.

### 2. For each configured project, fetch tickets via MCP
For each project entry in `jira.projects`:
- Build MCP tool name: `mcp__{project.mcp_server}__jira_search`
- Build JQL: `project = {project.project_key} AND assignee = '{project.assignee_filter}' AND status in ('{status1}', '{status2}', ...)`
  - If `assignee_filter` is empty, use `{config.daily.assignee_name}` from config.yaml as fallback
  - Statuses come from `project.sync_statuses` array
- Call `mcp__{project.mcp_server}__jira_search` with the JQL
- If MCP tool fails or returns error: log warning `"Jira sync failed for {project.project_key}: {error}. Skipping."`, continue to next project
- For each ticket in results, call `mcp__{project.mcp_server}__jira_get_issue` with `issue_key` to get full details (relationships, subtasks, epic)

### 3. Write/update ticket notes in 06 Jira/
For each fetched ticket, write to `VAULT/{config.structure.jira_notes}/{ticket.key}.md`:

Frontmatter fields (per D-03):
```yaml
---
key: {ticket.key}
summary: "{ticket.summary}"
status: {ticket.status}
assignee: {ticket.assignee}
priority: {ticket.priority}
project: {project.project_key}
sprint: {ticket.sprint_name or ""}
due_date: {ticket.due_date or ""}
created: {ticket.created_date}
epic: {ticket.parent_epic_key or ""}
type: {ticket.type}
last_sync: {ISO 8601 timestamp of current sync}
tags: jira
---
```

Body:
```markdown
# {ticket.key}: {ticket.summary}

**Status:** {status} | **Priority:** {priority} | **Sprint:** {sprint or "—"}

## Relationships

- **Epic:** [[{epic_key}]] (or "—" if none)
- **Linked issues:** [[{linked_key1}]], [[{linked_key2}]] (or "—" if none)
- **Subtasks:**
  - [[{subtask_key}]] - {subtask_summary} (or "—" if none)
```

Per D-04: Re-sync overwrites ALL frontmatter and regenerates the body. Jira is source of truth. No user-editable sections preserved.

### 4. Determine inbox-worthy changes (per D-05)
Compare current ticket data against existing note frontmatter (if note existed before this sync):
- **New ticket** (no prior note in `06 Jira/`): create inbox item IF assignee matches user
- **Status changed to action-requiring status**: create inbox item. Action-requiring statuses are transitions TO any status in `project.sync_statuses` that wasn't the previous status. Specifically, transitions TO "To Do" (newly assigned), "In Review" (needs review action).
- **All other updates**: update note silently, NO inbox item

### 5. Write inbox items
For each inbox-worthy ticket, check `VAULT/{config.structure.inbox}` for existing wikilink `[[{ticket.key}]]` (per D-11 dedup). If NOT already in inbox, append:

New assignment format:
```markdown
- Jira [[{ticket.key}]] -- Asignado: {summary} ({YYYY-MM-DD})
```

Status change format:
```markdown
- Jira [[{ticket.key}]] -- Status changed to "{new_status}": {summary} ({YYYY-MM-DD})
```

### 6. Enrich with wikilinks
For ticket notes and inbox items:
- Match assignee/reporter names against `VAULT/{config.structure.people}/` filenames -- add `[[Person Name]]` if match found
- Match project context against `VAULT/{config.structure.projects}/` -- add project wikilink if applicable

### 7. Graceful degradation table

| Problem | Behavior |
|---------|----------|
| Jira MCP server unavailable | Skip that project, warn, continue with other projects |
| JQL returns error | Log error with JQL text, skip project, continue |
| JQL returns empty results | Log "No tickets found for {project_key}", continue |
| Single ticket fetch fails | Skip that ticket, log warning, continue with others |
| 06 Jira/ folder missing | Create it |
| connectors.yaml missing jira section | Warn user to configure, skip Jira sync entirely |
| No assignee_filter and no config.daily.assignee_name | Sync all tickets regardless of assignee, warn user |
| Inbox file missing | Create it with `# Inbox` header, then append |

**Output:** Updated ticket notes in `VAULT/{config.structure.jira_notes}/`, optional inbox items in `VAULT/{config.structure.inbox}`.

**Important Rules:**
- Never abort on partial failure -- process as many projects/tickets as possible
- Always update `last_sync` in frontmatter on every sync (enables staleness detection)
- Wikilinks in Relationships section enable Obsidian graph connectivity
- The skill reads Jira data via MCP, never via HTTP API directly
- Spanish language for all user-facing output (warnings, summaries)
